## Speed from first principles

Each round requires two information stages: three independent simultaneous messages, then three independent prices after all three messages are visible. Thus six model requests per round. Merging messages/prices removes current-message information and changes the game. Combining three firms into one generation changes their independence and private-system information. Removing histories/rounds changes the task. Smaller/quantized models and backend migrations require separate provenance and cannot be assumed numerically equivalent.

Safe engineering candidates preserve exact per-firm messages, seeds, schemas, observations, stage barriers and action selection. Exact full-request replay of already produced identical requests is already implemented. Shared neutral preparation is already reused where genuinely identical. Runtime cache maintenance reclaims memory without changing requests, with logs and numerical caveats. A C-first request schedule passed offline exact-input replay but showed no reliable isolated timing advantage; not installed. Request concurrency can preserve information boundaries only on a backend with independent sampling streams; on this memory-limited Mac it can increase memory pressure and queueing. A larger-memory machine with the same runtime/weights is the cleanest hardware continuation; a GPU backend is a documented new execution configuration requiring calibration.

The dominant cost is repeated prompt processing rather than long model answers. Further changes should be justified by actual steady-state timings, not memory reduction alone or warm-cache repetitions of one frozen request. Existing microbenchmarks and maintenance probes are separate development calls, never additional experimental observations.
